# How chapter pictures work

Notes for whoever changes the Illustrate page (`src/app/c/[id]/illustrate/page.tsx`), and the file to read before touching it. All ComfyUI calls are made from the browser, never from the StoryTime server. Planned work is in `TODO.md`; how to set up ComfyUI is in `docs/pictures.md`.

- **Components** (`src/components/`): `IllustrateWorkspace` holds the state shared by the page (the prompt loaded from a picture, the starting picture, and all of the chapter's pictures as `Picture`s from `pictures.ts`: the page's jobs, then those made on this visit, marked `fresh`) and lays out the two columns: `.illustrate-controls` (the `IllustrateChapter` panel, passed in by the page, then `ImagePromptPanel`: prompt, then `ComfyGenerate`) and `.illustrate-gallery` (the two `ChapterImageEditor` cards first, to compare new pictures with, then `ChapterPictures`). In one column (narrower than 64rem) the two `ChapterImageEditor` cards come first, above the chapter panel (CSS: the gallery is `display: contents` and the cards have `order: -1`). On a wide screen (64rem) the controls column is sticky and the page uses up to 120rem. `ComfyGenerate` makes one picture per click (there is no How many menu; `settings.comfy.count` is left over and unused): clicks with nothing changed, each within 0.8 s of the last (`GATHER_MS`), are gathered into one job of up to 8 pictures (`MAX_BATCH`), and a click with anything changed sends the gathered job at once and starts another. Several jobs can wait in ComfyUI's queue, each with the prompt and settings as they were when asked for. It hands the jobs being made up through `onQueue` (as `PendingJob`s, newest first, each with its `stop`) and each finished job's pictures through `onPictures`; `ChapterPictures` shows each job as a place kept for each of its pictures (`li.comfy-pending-tile` in the picture grid, at the size setting's shape, or the starting picture's once it is uploaded), with the job's progress drawn over each place (only the first is a `role=status`, and has Stop). Stop only interrupts a job ComfyUI's `/queue` says is running, since older ComfyUIs interrupt whatever is running.
- **The Pictures panel** (`ChapterPictures`) is a timeline, newest first: the jobs being made (newest first, so the one running is last, next to the newest pictures), then the pictures. `timeline()` in `pictures.ts` puts neighbours made with the same prompt, negative prompt, checkpoint, moment, starting picture and strength (and size, from the prompt alone) in one group, so two batches in a row share a group and A, B, A is three groups; a job being made joins the newest group when its settings match. Groups have no heading, only a line between them (`.picture-group`'s top border); each group's list is named `Pictures from “<prompt>”` for screen readers (and the tests). Other chapters likewise shows only the chapter titles, with a line between jobs. Jobs being made join the groups in Pinned & new and All; in Rejected and Other chapters they show on their own at the top. Views (`inView` in `pictures.ts`): **Pinned & new** (default: pinned, plus this visit's unmarked ones until Clear unpinned), **All** (everything not rejected), **Rejected**, and **Other chapters** (`OtherChapterPictures`: the story's other chapters, paged, through `?story=&not_chapter=`). So on return only pinned pictures show. Clear keeps nothing on the server. Each picture has a row of round buttons on its top right corner (`PictureButtons`, shared by `PictureTile` and the full-size viewer, so they look and sit the same in both): pin (a thumbtack, filled when pinned) and reject (✕, ↺ to restore), and a ☰ menu with Use as header picture and Use as footer picture (icons from `PictureIcons.tsx`; the slot it is in reads "This is the header picture" and is marked unavailable), Start from this, Load prompt, Info and Open in a new tab. **Info** (`PictureInfo`, a modal `<dialog>`, also over the viewer and for Other chapters' pictures) shows the prompt, negative prompt and `pictureDetails()` (chapter and moment, when made, checkpoint, size, seed, batch size and index, starting picture and strength, file), with Copy prompt, Copy negative prompt, Copy all as Markdown (`pictureMarkdown()`, prompts in code blocks), Load prompt and Start from this. Copying works over plain http too (`copyText` falls back to a hidden text box, put inside the dialog because the page behind a modal can't be selected). The workflow's other settings (sampler, steps, CFG) aren't recorded, so Info can't show them. Choosing an item puts the keyboard back on ☰. A mark change saves at once, is put back if the server refuses, and offers Undo. The picture that is the chapter's header or footer now has a badge on its top left corner (here and in the viewer): `chapter_images.image_index` (migration 15) says which of the job's pictures was saved, sent as `PUT .../images/:slot?job=<id>&index=<n>`; one saved before that is only recognised when its job made a single picture. Clicking a picture opens `PictureViewer` (a modal `<dialog>`, whole screen) on it, going through the view's pictures in the order shown: ← → or a swipe, P pins, X rejects (a picture that leaves the view moves the viewer on), Esc closes (or closes the ☰ menu when it is open). In the viewer the picture sits in a frame of its own shape (`.viewer-frame`, sized with container units), so its buttons and badge are on its corners as on a tile. Ctrl/Cmd/Shift or middle click still opens the picture in a new tab. `usePictureSaver` saves a picture as the header or footer.
- **ComfyUI code** (`src/lib/comfy/`): `client.ts` (HTTP and WebSocket calls, `uploadImage`), `workflow.ts` (filling a workflow; see below), `startPicture.ts` (`StartPicture`, `fromComfyImage`, `fromSaved`, `uploadStart`), `presets.ts` (the named presets, below).
- **Workflows.** Built-in SDXL text-to-image, and `BUILTIN_IMG2IMG` when a starting picture is chosen. A custom workflow (pasted in a drawing preset's card in Settings) is filled by placeholders (`{{prompt}} {{negative}} {{checkpoint}} {{width}} {{height}} {{count}} {{seed}} {{prefix}}`, and for image to image `{{image}} {{denoise}}`), or, with none, by finding the usual nodes. A custom workflow with no placeholders is started from a picture by swapping its `EmptyLatentImage` for LoadImage → VAEEncode → RepeatLatentBatch and setting every numeric `denoise` input; it needs a VAE (a `VAEDecode`'s link or a `CheckpointLoaderSimple`). `describeWorkflow(...).image` says whether a workflow can.
- **The job log** (`picture_jobs`; `src/lib/pictureJobs.ts`; `/api/picture-jobs`). One row per finished job: prompt, negative, checkpoint, size, seed, count, `moment`, `source` (`comfy:<subfolder/file>` or `saved:<chapter id>:<slot>`, null for text-to-image), `denoise`, and `images` (ComfyUI `{filename, subfolder, type}`). `GET ?story=` (optionally `&not_chapter=`) or `?chapter=` lists newest first, `limit` 1 to 200, and `next` is passed back as `before`; each job has `marks`, one per picture (`pinned`, `rejected` or null), from `picture_marks` (migration 13), set with `PUT /api/picture-jobs/:id/mark {index, mark}`. The Illustrate page loads the chapter's latest 1000 jobs with it (`chapterPictureJobs`). The pictures stay in ComfyUI and are shown through its `/view`, so a lost file shows "ComfyUI no longer has this picture".
- **The prompt boxes are kept per chapter and moment** (`picture_prompts`, migration 14, which replaced migration 12's `picture_drafts`; `src/lib/pictureDrafts.ts`; `GET/PUT /api/chapters/:id/picture-draft`): prompt, negative, scene and What to show, one set for Chapter start and one for Chapter end, so switching the "Picture for" menu brings each one's prompt back. The moment saved last is the one the page opens on (choosing a moment saves it). `PUT` takes one moment's boxes; `GET` gives `{moment, start, end}`. The page loads them with the chapter; `usePictureDraft` saves 0.7 s after typing stops, at once when the moment is switched, and sends a change still waiting (with `keepalive`) on `pagehide` or when the panel unmounts. Saves go one after another so the last one decides the moment. Not in the JSON export.
- **A saved header or footer** keeps the prompt and negative prompt that made it (`chapter_images.job_id/prompt/negative`, copied from the job by `PUT .../images/:slot?job=<id>`). Uploads keep none. The job log and `job_id` are not in the JSON export.
- **Jobs are tagged in ComfyUI:** `extra_data.storytime = {chapterId, storyId}`, and saved pictures are filed under `StoryTime/<story id>/<chapter id>` where the workflow's prefix is `StoryTime` or contains `{{prefix}}`.
- **Settings** (`settings.comfy`, in `src/lib/settingsSchema.ts`): url, width, height, `drawPresets`, `editPresets` and `editPreset` (the edit preset last used). A drawing preset holds a checkpoint, LoRAs, Redraw strength, sampler settings and an optional workflow; an edit preset holds one edit model's files, LoRAs, Fast box, default strength and sampler settings (`src/lib/comfy/presets.ts`). They are shared across stories and held on the server. (`count` and the top-level `imagePromptStyle` are left over and unused.)
- **The story's picture settings** (`StoryPictureSettings` on the story's details page, `#pictures`): prompt style (`stories.image_prompt_style`, tags or natural, null until chosen), art style (`stories.art_style`) and drawing preset (`stories.draw_preset`, migration 18; null follows the first preset). A chapter can choose another preset (`chapters.draw_preset`, null follows the story's), from the Make pictures panel. They keep a story's pictures alike, so they are the story's, not the chapter's or the app's. `stories.checkpoint` (migration 16) is only read once, to turn the checkpoints stories used into presets. The Illustrate page shows the story's settings in a line above the prompt, with a link to change them, and says which aren't chosen yet; prompts are written as tags until a prompt style is chosen. They are in the JSON export and import.
- **A story can have no chapters yet** (New story makes it from its title, summary and style notes). Its details page then shows Start writing (`/s/<id>/write`, draft key `first:<story id>`, posted with `POST /api/stories/<id>/first-chapter`); once it has a chapter, Read.
- **Freeing ComfyUI's memory for a text model:** each AI connection has `freeComfy`. When it is on and a ComfyUI address is set, `streamChat` first sends `POST /free {unload_models, free_memory}` (`freeComfyMemory` in `comfy/client.ts`; 3 s timeout, failures ignored). Not yet tried against a real ComfyUI.
- **Tests:** `tests/e2e/fakeComfy.mjs` is a fake ComfyUI (progress over WebSocket, `/view`, `/history`, `/upload/image`, a `fail` mode). The page's tests are the `tests/e2e/illustrate-*.e2e.mjs` files (`comfy`, `past`, `start`, `chapter`, `viewer`, `draft`, `resume`, `prompt`, `edit`, `presets`; the draft one with `tests/api/picture-drafts`); the workflow logic is in `tests/unit/comfy-workflow.test.mts`. Run some of them with `node tests/run.mjs e2e illustrate-viewer`.
